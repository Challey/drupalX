## 1. 一句话定位

**DrupalX = 面向政企门户与官方信息业务的「交钥匙」一键交付平台。**

客户用自然语言或页面选型说出需求后，平台完成：站点开通 → 门面气质 → 内容/业务移植 → 能力装配（商城、舆情等）→ 多端打包（Web / 小程序 / 安卓壳等）→ 可验收交付包。

把原本偏 **ToB 开通与配置** 的平台，做成前台像 **ToC 下单** 一样简单；复杂业务能力仍走策展半封闭 **App Store**（ToB 功能货架）。

---

## 2. 战略调整要点（相对现行表述）

| 维度 | 现行（仍保留为底座） | 调整后主叙事 |
|------|----------------------|--------------|
| 口号 | 中小企业 AI 数字门户 / 基础平台 + App Store | **政企门户交钥匙工程**（Turnkey Portal Delivery） |
| 入口体验 | 控制台开通租户、后台选包 | **订单式交付台**：说需求 / 点选型 → 一键生成 |
| 客户感知 | SaaS 租户管理员 | **下单客户**（单位经办人也可自助）；专业运维仍在后台 |
| 行业纵深 | SME + 政务并提 | **政企优先**：规范性、可信度、专业性为硬门槛 |
| 与通用 Agent 平台 | 未对比 | **非 Manus 式通用任务 Agent**；是行业交付 OS |
| 变现与扩展 | Foundation → Store → Channel | **交付订单（主）** + **App Store 增值（深）** |

现行五性（安全/稳定/快速/可扩展/可伸缩）+ UI、苹果式半封闭商店、Theme Studio、混合 SaaS 隔离 **全部保留**，上移为交钥匙流水线的工程约束，而不是产品口号本身。

## 3. 与 Manus 等通用 Agent 的差异

| | 通用 Agent（如 Manus 类） | DrupalX 交钥匙 |
|--|--------------------------|----------------|
| 对象 | 任意任务 / 开放网页与工具 | **政企门户与官方信息业务**固定品类 |
| 产出 | 会话结果、临时站点/脚本 | **可运维、可审计、可验收的交付物**（租户站 + 许可能力 + 多端） |
| 信任模型 | 模型能力与工具调用 | **策展供应链 + 租户隔离 + 合规门禁** |
| 规范 | 弱行业模板 | 政府气质门面、公文/资讯结构、权限与留痕、可限制 trust tier |
| 复杂度入口 | 对话即一切 | **对话选型 + 表单选型双通道**；深水区进 App Store |
| ToB/ToC | 偏个人生产力 | **前台 ToC 下单体验，后台 ToB 平台与商店** |

核心主张：**在「高专业、高可信、高规范」赛道做垂直交钥匙，而不是做通用数字员工。**

## 4. 产品形态：双层体验

```
┌─────────────────────────────────────────────────────────┐
│  交付台（ToC 体验）  /order · /deliver · 对话向导        │
│  下单 · 选型 · 预览蓝图 · 一键生成 · 进度与验收清单       │
└────────────────────────────┬────────────────────────────┘
                             │ 生成 Delivery Blueprint
                             ▼
┌─────────────────────────────────────────────────────────┐
│  交付引擎（平台）  provision · theme · migrate · enable │
│  · package channels · acceptance report                 │
└───────────────┬─────────────────────┬───────────────────┘
                │                     │
                ▼                     ▼
┌───────────────────────┐   ┌─────────────────────────────┐
│ 租户门户（交付物）     │   │ App Store（ToB 深水区）      │
│ Web 主站 · 内容 · 业务 │   │ 商城/舆情/支付/OSS… 策展启用 │
└───────────────────────┘   └─────────────────────────────┘
```

- **ToC 层**：客户只感知「我要什么门户 + 要哪些能力 + 要哪些端」。
- **ToB 层**：开发者上架、审核、许可、分成、信任分级；政务默认可收紧 `community` 包。

## 5. 两种需求入口（必须同时提供）

### 5.1 自然语言下单（对话）

客户描述例如：

> 「做政府门户；把原 xx.gov.cn 资讯和办事入口迁过来；要商城和舆情监控；打微信小程序，再给安卓 APP。」

系统产出 **Delivery Blueprint（交付蓝图）** JSON/实体，经客户确认后一键执行。

### 5.2 页面选型下单（向导）

分步勾选，少填空：

1. **站点类型**：政府门户 / 企事业单位门户 / 行业站点（可扩展）
2. **门面气质**：Theme Studio 政企 packs（沉稳/亲民/进取/苹果风等）
3. **内容来源**：空白起步 / 演示行业包 / **旧站移植**
4. **能力清单**：App Store 策展能力多选（商城、舆情、支付、OSS、AI 客服…）
5. **交付端**：Web（必选）· 微信小程序 · PWA/可安装壳 · 安卓打包（范围见 §8）
6. **确认蓝图 → 一键交付**

两种入口 **共用同一 Blueprint 模型**，避免两套开通逻辑。

## 6. 交钥匙流水线（交付引擎）

一键交付 = 编排下列阶段；任一步失败可重试且有审计日志。

| 阶段 | 名称 | 做什么 | 现有能力锚点 |
|------|------|--------|--------------|
| D0 | 下单与蓝图 | 对话/向导 → Blueprint 确认 | **新建** `dx_delivery`（建议） |
| D1 | 租户开通 | 独立库 + multisite + 域名 | `dx_platform` / `TenantProvisioner` |
| D2 | Foundation Pack | 政务/企事业 recipe + 内容类型 | recipes · `dx_portal` |
| D3 | 门面 | Theme Studio pack + 白标 | `dx_theme` |
| D4 | 旧站移植 | 抓取/导入资讯·栏目·附件·基础业务映射 | **新建** 迁移适配器（爬取/RSS/API/手工包） |
| D5 | 能力装配 | 按蓝图审批/白名单启用商店包 | `dx_appstore` |
| D6 | 多端打包 | Channel API + 小程序模板 + PWA；安卓见范围 | 规划 Channel · 现有 PWA 壳 |
| D7 | 验收交付 | 验收清单、预览链接、运维手册摘要、SLA 入口 | **新建** Acceptance Report |

「交钥匙」对客户的可感知结果：

1. 可访问的正式/预发门户 URL  
2. 已选气质与品牌已生效  
3. 约定内容已迁入或明确待人工项  
4. 已购能力已启用且可点进业务  
5. 约定端已出包或出预览二维码  
6. 一份验收对照表（通过 / 待补）

## 7. 能力货架（交付时可勾选）

交付台展示的是 **客户语言**；底层映射 App Store `category` / 包。

| 客户选项（示例） | 映射方向 | 备注 |
|------------------|----------|------|
| 官方资讯 / 通知公告 | Foundation 内容类型 | 底座必选 |
| 产品与企业介绍 | `dx_portal` | 已有 |
| 商城 / 在线订购 | `commerce` 类包 + 结账 | 已有支付/结账骨架 |
| 舆情监控 | 新策展包 / 对接外部舆情 SaaS | **需立项**（合规与数据源敏感） |
| AI 客服 / 知识问答 | `dx_ai_gateway` | 已有 |
| 对象存储 / 大附件 | `dx_oss` | 已有 |
| 微信小程序 | 官方模板 + Channel API | 战略已定，工程待加深 |
| 安卓 APP | 见 §8 边界 | 避免承诺「任意原生工程生成」 |
| 支付（微信/支付宝） | `dx_payment` | 已有 |

政务租户默认：**仅 `platform` / `security`（及明确批准的）trust tier**；与 [module-curation.md](module-curation.md) 一致。

## 8. 多端边界（必须写清，避免过度承诺）

| 端 | 交钥匙含义（建议采纳） | 不做（除非单独项目） |
|----|------------------------|----------------------|
| Web | 租户门户主站，正式交付物 | — |
| PWA「App」 | 可安装品牌壳，同源内容 | 完整原生 iOS 工程生成器 |
| 微信小程序 | 官方模板对接 Channel API | 客户任意第三方小程序源码乱接 |
| 安卓 | **品牌壳 APK/AAB 或受控壳工厂**（WebView/PWA 打包 + 推送等有限原生能力） | 租户侧拖拽生成任意原生业务 App；安卓式旁加载任意包 |

与现行 strategy「多端快速生成」对齐，并显式纳入客户口语中的「安卓 APP」，但落在 **受控壳**，不是通用 App 工厂。

## 9. 旧站移植（专业性关键路径）

移植是政企迁建的核心痛点，建议分级：

| 级别 | 范围 | 自动化期望 |
|------|------|------------|
| L1 | 栏目结构 + 列表/正文 HTML + 附件 | 高（模板化站点） |
| L2 | 办事入口链接、表单线索、通讯录等结构化块 | 中（需映射规则） |
| L3 | 原业务系统（审批流、库表耦合） | 低 → **Blueprint 标为人工/集成项目**，不假装一键 |

原则：**能自动的进一键流水线；不能自动的进入验收清单「待办」并报价人工**，保持可信，避免「全自动幻觉」。

---

## 10. 规范性 · 可信度 · 专业性（行业门槛）

相对消费级建站，政企交钥匙额外强制：

1. **视觉规范**：政府/企业气质 packs，禁止未审 CSS 旁加载（Theme Studio 半封闭）。  
2. **供应链**：Composer lock + 商店审核；政务信任分级。  
3. **数据隔离**：每租户独立库与文件目录（现行 1C）。  
4. **审计**：交付流水线每步操作者、时间、蓝图版本可查。  
5. **内容安全**：导入内容的审核队列（尤其旧站 HTML）。  
6. **等保/密评友好叙述**：架构上预留日志、权限、备份与域名 HTTPS；具体认证不作为 MVP 阻塞，但文档与默认配置朝此靠拢。  
7. **舆情等敏感能力**：默认不「野路子爬全网」；优先合规数据源与授权接入。

## 11. 商业模式草图（确认向）

| 层 | 模式 | 说明 |
|----|------|------|
| 交付订单 | 套餐价 / 项目价 | 按站点类型 + 移植级别 + 端数量计价 |
| 订阅 | Starter / Growth / Enterprise | 现行套餐模型可挂在交付物上 |
| App Store | 买断 / 订阅 + 分成 | 深水区 ToB；开发者生态 |
| 人工加项 | L3 集成、定制主题、驻场 | 交付台引导到工单，不假装全自动 |

前台是 **ToC 下单转化**；利润与护城河在 **可信交付 + 策展商店 + 运维**。

## 13. 路线波次（无日历工期；确认后启动）

> 编号建议自 **Phase DX**（Delivery eXperience）起，与历史 A–DW 区分。

### Phase DX — 交付台 MVP（确认后第一优先）

- Blueprint 数据模型与确认页  
- 页面选型向导（无对话也可下单）  
- 串联：开通 → Pack → Theme → 可选商店包启用  
- 验收报告 v1（链接 + 清单）

### Phase DY — 对话下单

- 需求对话 → 蓝图草稿（可复用 AI 网关）  
- 客户改勾选后确认执行  

### Phase DZ — 旧站移植 L1/L2

- 适配器框架 + 1～2 个常见门户模板  
- 导入审核队列  

### Phase EA — 多端交钥匙

- Channel API 最小集  
- 微信小程序官方模板  
- 安卓受控壳工厂（范围锁定后）  

### Phase EB — 行业能力加深

- 舆情等敏感包的合规接入与商店上架  
- 政务 trust 默认策略产品化  

并行原则：**未确认本设计前，不启动 DX+ 代码**；Theme Studio / 商店 / AI 等底座可继续加固。

## 14. 成功标准（产品，而非仅技术）

1. 非技术经办人可在无培训下用向导或对话完成下单并看懂蓝图。  
2. 标准「政府门户 + 气质包 + 资讯起步 + Web」可一键出可预览站。  
3. 勾选商城等已上架能力后，交付站内可完成主路径点击。  
4. 旧站 L1 有可演示的自动导入 + 人工待办透明。  
5. 客户口头「要小程序/安卓」时，系统给出与 §8 一致的可达交付物，而非空头承诺。  
6. 全程可审计；政务信任策略默认可收紧。
